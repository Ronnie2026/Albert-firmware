# CAN 转发与抓包隔离版本 v1.0.3

独立入口：`src/can_gateway.cpp`；PlatformIO 环境：`can_gateway`。现有回放器、分析仪和默认构建环境保持原样。页面内嵌在固件中，不需要烧录文件系统。

## 默认行为

| 接收方向 | 默认策略 | 发送目标 |
| --- | --- | --- |
| TWAI / CAN_B | 正向转发开启；精确匹配下方 67 个标准 ID | MCP2515 / CAN_A |
| MCP2515 / CAN_A | 记录全部有效报文；回传开关关闭且白名单为空 | 只有手动开启并命中回传白名单才发往 TWAI |

只透传标准数据帧，原样保留 ID、DLC、数据，不修改业务位。扩展帧、RTR、DLC > 8 和异常帧均不得进入转发路径。可正常读出的扩展帧/RTR 会记录；MCP2515 库无法解码的 DLC > 8 计入读取错误；CRC 等物理层错误以控制器诊断展示，不作为有效数据帧记录。

## 编译、烧录和访问

```bash
pio run -e can_gateway
pio run -e can_gateway -t upload
pio device monitor -b 921600
```

也可以用现有脚本：`./compile.sh -e can_gateway -u -m`。

- 应用固件：`.pio/build/can_gateway/firmware.bin`。
- Wi-Fi 热点：`CAN-Gateway`。
- 热点密码：`12345678`。
- 热点下浏览器地址：`http://192.168.4.1`；连接路由器后，也可使用页面显示的局域网 IP。
- 两路速率：500 kbit/s。
- MCP2515 默认晶振：16 MHz，与工程原驱动一致。8/20 MHz 板可在此环境的 `build_flags` 加 `-D GATEWAY_MCP_CLOCK_MHZ=8` 或 `20`。
- 热点名和密码可用 `GATEWAY_AP_SSID`、`GATEWAY_AP_PASSWORD` 编译宏覆盖。
- 页面提供基于内置录制数据的 MCP2515 离车模拟回放，无 BLE OTA。

沿用 `libraries/private_library/pin_config.h` 的板级引脚：TWAI TX=7/RX=6；MCP2515 CS=10/RST=9/INT=8；SPI SCLK=12/MOSI=11/MISO=13。GPIO8 用作 MCP INT，不作为 LED 输出。

## 页面操作

1. 连接热点后打开页面，确认两侧就绪、速率和晶振符合硬件。
2. 默认正向白名单已填写 67 个 ID，包含一档消息 `0x331`。修改后点击“应用并保存”。所有 ID 按十六进制解释，支持 `0x` 前缀、空格/换行/逗号/分号分隔；合法范围 `0x000–0x7FF`，重复值去重；空列表拒绝全部。
3. 需要回传时，填写“回传白名单”，勾选“开启 MCP2515 → TWAI 白名单穿透”，应用保存。只改白名单但不开开关仍然不会回传。
4. 监视器可以按来源、ID 和结果筛选。筛选条件在设备上生效，切换条件会开始新的抓包历史。显示设备微秒时间、方向、帧类型、DLC、数据和最终转发结果，支持暂停抓取及 CSV 导出。
5. “停止转发和模拟”停止回放，关闭并保存两侧转发开关，仍抓包。“恢复默认 67 个 ID”恢复出厂策略，包含开启正向、关闭回传并清空回传白名单。

NVS namespace 为 `can-gateway`，配置带版本和校验。每次启动加载最后保存的有效配置；损坏/缺失时使用上述默认值。控制器初始化失败则在运行时关闭两个方向，不自动继续转发；检查硬件后重新应用配置。页面显示保存失败时，运行配置已改变，但重启仍可能加载原保存值。

配置切换由 CAN 任务执行，短暂停止控制器并清空两侧 RX/TX 缓冲后应用新策略；期间存在接收空窗。网页的 `202` 表示已排队，不表示生效；以状态中的 `apply.pending=false`、修订号和结果为准。已经开始上总线的帧无法撤回。写接口需要当前启动会话 token，用于防跨站误操作，不是独立用户鉴权；可访问设备的热点或局域网客户端均可通过网页管理设备。

## 连接 Wi-Fi 路由器

1. 首次连接 `CAN-Gateway` 热点（密码 `12345678`），打开 `http://192.168.4.1`。
2. 在“Wi-Fi 连接”点击“扫描附近 Wi-Fi”并选择网络，也可手动填写名称来连接隐藏网络。支持 2.4 GHz 开放网络或 WPA2/WPA3 个人网络；不支持 5 GHz、企业账号认证或网页认证流程。
3. 输入密码，点击“保存并连接”。空密码明确表示开放网络；已有密码不会回填。只想使用之前的配置时，点击“重连已保存网络”。
4. 页面显示“Wi-Fi 已连接”后，局域网中的手机/电脑可以通过显示的设备 IP 打开同一页面。路由器需允许客户端互相访问。`CAN-Gateway` 热点仍保持开启。

SSID 按 UTF-8 字节校验，范围 1–32 字节；密码允许空值、8–63 字节口令或 64 位十六进制 PSK。配置原子保存为独立 NVS namespace `gateway-wifi` 下的 `credentials` blob，保存失败不会切换网络。状态与扫描 API 不返回密码，串口不输出密码。

Wi-Fi 采用 AP+STA 模式，连接和扫描不等待完成，不暂停 CAN 任务或改变转发/模拟规则。每次连接尝试最多等待 15 秒，失败或掉线后等待 30 秒再重试；重启自动连接已保存网络。“断开 Wi-Fi”只停止本次运行的连接与重试，保留配置；“忘记网络”删除配置并断开，重启后不再自动连接。连接/扫描期间不能再启动另一轮扫描，等待完成或断开后可重试。

AP 与 STA 共用无线信道，连接路由器时热点客户端可能短暂掉线并重新连接；热点 IP 保持 `192.168.4.1`。本功能用于让网关加入局域网，不提供热点到路由器的 NAT 上网转发。Wi-Fi 操作的 202 表示请求已接受，连接结果以 `wifi.connected`、`wifi.state`、`wifi.message` 和 `wifi.ip` 为准。

## 离车模拟发送

连接 MCP2515 / CAN_A 侧的目标设备，在网页“离车模拟 → MCP2515”选择来源、发送间隔和是否循环，点击“开始模拟”。数据直接来自 `src/replay_frames.cpp` / `.h`，共 19,068 条；`bus=0` 的 CAN_A 数据有 10,266 条，`bus=1` 的 CAN_B 数据有 8,802 条。默认只选择 CAN_A，可选择 CAN_B 或全部，所有模拟帧均发往 MCP2515。

- 模拟上电关闭，每次启动从第 0 条开始；默认循环、发送间隔 357 µs，目标约 **2800 帧/s**，可设置 357–1000000 µs。录制数据不含时间戳，未选中的来源直接跳过，不占发送间隔。CAN 任务使用微秒定时器等待下一帧，轻微调度抖动保持原节奏，错过完整间隔后不会突发追赶；实际成功速率受白名单、CPU 调度、SPI、ACK 和总线负载影响。
- ID、DLC、数据保持原样，使用**已生效的正向 ID 白名单**。模拟启动开关独立于 TWAI 正向转发开关；不受 TWAI 硬件接收掩码限制。空白名单会拦截所有模拟帧。
- 每轮回放开头额外发送一次一档消息 `0x331 / DLC 6 / 24 00 00 00 00 00`，选择 CAN_A、CAN_B 或全部均包含该帧，并占用一个正常发送间隔。该帧也经过正向白名单，默认已包含 `331`；设备若保存了旧配置，可在网页中加入 `331` 并应用，或恢复默认配置。状态中的总条数包含此帧，为 19,069 条。
- 模拟不会主动向 TWAI 发送。真实接收及转发仍按现有网关规则执行，MCP 侧设备回复默认只记录；开启回传后，回复仍受回传白名单限制。
- “停止模拟”停止读取并申请取消未完成的模拟帧，不改变网关配置。修改/恢复转发配置、总停止、MCP 故障或设备重启均会停止模拟。已经开始上总线的帧可能完成当前发送，无法撤回。关闭网页或暂停监视器不会停止模拟。
- 模拟帧在日志中标为“模拟 → MCP”，来源筛选可选“模拟发送”，继续使用 2000 条匹配历史。CSV 来源为 `SIMULATED`、目标为 `MCP2515`。设备回复标为 MCP2515 接收。
- 页面显示数据位置、完成轮次、提交、成功、白名单拦截、忙、失败、过期和取消计数。成功以 MCP TXnIF 完成事件为准；每次成功启动新回放时重置模拟计数。单次读完数组后停止调度，已提交帧继续完成或超时。

## TWAI 硬件预过滤

采用 ESP-IDF 4.4 系列的 TWAI single filter。

- `auto`：计算正向白名单所有 ID 的共同位，生成不会误杀白名单的硬件 code/mask。
- `off`：接收全部，仍经过软件精确白名单。
- `manual`：输入 11-bit code/mask。页面 mask 的 **1 表示必须匹配**，0 表示忽略，例如 `code=0x100, mask=0x700` 接受 `0x100–0x1FF`。手动过滤若排除了正向白名单任一 ID，整个配置提交失败。

网页显示 ID 域有效 code/mask 和白名单数，状态 API 还提供实际写入驱动的 32-bit `acceptance_code/acceptance_mask`。ESP-IDF acceptance mask 的位极性与页面 mask 相反。

**默认 67 个 ID 覆盖所有 11-bit 位的变化，共同位掩码为 `0x000`，因此默认硬件层不会缩小接收范围；准确拦截由软件完成。** 这不是 67 个独立硬件过滤槽。改成更集中的 ID 子集，自动硬件掩码才可能减少接收负担。硬件拒收的 TWAI 帧不进入软件、统计和监视器；若要抓取全部 TWAI 报文，选择 `off`。

MCP2515 使用零掩码接收全部有效 STD/EXT 报文，回传白名单只控制发送，不裁剪这一路抓包。禁用会将损坏报文片段装入缓冲的 RXM=11 调试模式。

## 记录、发送和容量边界

- CAN 任务独占 TWAI/SPI，运行于 Core1，MCP INT 唤醒，TWAI 每 tick 轮询；Web 在 Arduino loop 中处理，不直接操作 CAN 驱动。
- 设备使用 1024 条原始 RAM 环形记录。网页设置来源、结果或 ID 筛选后，设备使用独立的 2000 条 PSRAM 环形缓存，只将匹配且已有最终结果的帧写入其中；无关帧不会挤掉匹配历史。PSRAM 分配失败时筛选接口会报错。浏览器最多保留 2000 条匹配帧，表格显示最新 300 条；CSV 导出浏览器当前持有的匹配记录，不是设备历史全量导出。
- 筛选条件是设备当前运行时的共享临时条件，不保存到 NVS；网页首次连接、刷新或切换条件会重置设备匹配历史。多个网页同时修改条件会相互覆盖，页面会重新同步。关闭页面后设备继续按最后条件记录，重启恢复未筛选模式。
- `/api/frames` 每次最多 128 条，浏览器落后时显示覆盖丢失数量。页面暂停仅停止抓取，不停止硬件收发；设备继续覆盖旧记录。
- TWAI RX 软件队列 256；TWAI TX 无软件排队、最多一帧在途；MCP2515 使用三个硬件 TX 缓冲。发送忙则立即丢弃并计数，没有无限重试或离线补发。
- 两侧发送使用 single-shot 模式；总线仲裁失败、缺少 ACK 等也可能丢帧。最长 20 ms 的待发时间后请求中止。MCP2515 已开始发出的帧可能完成当前发送，过期结果表示已申请取消，不保证远端没见到该帧。
- `submitted` 仅代表进入发送流程；`sent` 基于 TWAI TX_SUCCESS / MCP TXnIF 成功完成，不把写入控制器当成成功；它也不证明目标应用消费了报文。
- 物理层错误和 RX 溢出独立展示。MCP 溢出是检测到并清除的溢出事件数，不能当作精确丢帧数量；TWAI 硬件累计计数在驱动重装时重置。
- 控制器不请求自身发包回收。外部节点将报文再发回来会作为新帧处理，不按内容盲目去重；白名单双向重叠且外部有其他转发器时，需要避免形成外部回环。
- 两侧工作于 normal 模式并会 ACK。这里的“隔离”是应用层跨总线数据过滤，不是 listen-only、物理断开或电气隔离。
- 高负载时可能发生硬件溢出、发送忙或网页记录覆盖。本版本不承诺无损抓包或满总线吞吐；需在双 CAN 测试台验证所需流量和时延。

## HTTP 接口

| 方法和路径 | 用途 |
| --- | --- |
| `GET /api/status` | 生效配置、会话 token、apply 修订号、收发统计、replay/Wi-Fi 状态和硬件诊断 |
| `GET /api/frames?after=0` | 增量抓包，返回 next/latest/oldest/lost/capacity/revision/frames |
| `POST /api/capture-filter` | 设置临时抓包条件 `{bus: 0/1/2/3, result: 0/1/2/3, id: "0x082"}`；bus=2 表示全部来源、3 表示模拟；result=0 表示全部结果，空 ID 表示全部 ID |
| `POST /api/config` | 完整校验配置，排队应用并保存 |
| `POST /api/defaults` | 恢复并保存默认策略 |
| `POST /api/stop` | 停止模拟，关闭并保存双向转发开关 |
| `POST /api/replay` | 启动/停止临时模拟发送，不写 NVS |
| `POST /api/wifi` | 保存连接、重连、断开或忘记 Wi-Fi 网络 |
| `POST /api/wifi/scan` | 异步启动附近 2.4 GHz Wi-Fi 扫描 |
| `GET /api/wifi/scan` | 扫描状态及最多 30 个网络的 SSID、RSSI、是否开放 |

POST 使用 `Content-Type: application/json` 和 `X-Gateway-Token`，token 从 status 读取。

保存并连接 Wi-Fi：`{"action":"connect","ssid":"My WiFi","password":"your-password"}`；使用已保存配置：`{"action":"reconnect"}`；断开但保留配置：`{"action":"disconnect"}`；删除配置并断开：`{"action":"forget"}`。扫描 POST 的请求体为 `{}`，随后 GET 轮询，直到 `scanning=false`；扫描结果中的 SSID 仅作为文本显示。

启动约 2800 帧/s 模拟：`{"enabled":true,"source":0,"interval_us":357,"loop":true}`；停止：`{"enabled":false}`。`source` 是原始录制来源（0=A，1=B，2=全部），与监视器的来源编码不同。返回 202 仅表示排队，以 status 中 `replay.pending=false`、`replay.revision`、`replay.ok` 和 `replay.running` 确认执行结果。`/api/frames` 的模拟帧 `bus=3`；筛选状态下的增量游标取响应 `next`，不要使用帧本身的原始 `seq`。

配置示例（用自己的正向 ID 替换示例列表）：

```json
{
  "forward_enabled": true,
  "reverse_enabled": true,
  "forward_ids": "0x082 0x102 0x103",
  "reverse_ids": "0x123",
  "hardware_mode": "auto",
  "hardware_code": "0x000",
  "hardware_mask": "0x000"
}
```

python3 -m unittest discover -s tests -p 'test_can_gateway_policy.py' -v

策略测试包含完整标准 ID 空间、STD/EXT/RTR 区分、空/非法/最大长度白名单、硬件掩码覆盖和 NVS 单字节损坏；回放测试编译真实录制数据，验证来源、白名单、单次/循环、停止/重启和延迟不追赶；均使用 AddressSanitizer/UBSan。网页测试使用真实 Chromium 加模拟 HTTP 接口，覆盖模拟启动/停止/拒绝、模拟帧筛选与 CSV、总停止、重启不自动回放，以及原有监视器和转发控件。

Wi-Fi 主机测试使用模拟驱动验证凭据边界、保存失败、重启自动连接、超时/断线重试、扫描与连接互斥、断开/忘记、计时回绕及热点保留；浏览器测试覆盖扫描选择、SSID 文本处理、字节校验、连接/重连/断开/忘记、密码清空和草稿保留。真实路由器的认证、DHCP、信道切换和无线断线恢复仍需实机验证。

实机验收应至少覆盖：默认 67 个 ID 正向允许、非白名单拦截；MCP 默认无回传；回传白名单仅放行指定 STD 数据帧；相同数值 ID 的 EXT/RTR 不穿透；重启保持配置；修改/关闭规则不发送旧队列；断开 ACK、bus-off、高流量和无硬件时诊断正常。本次代码验证不能替代这些硬件测试。
