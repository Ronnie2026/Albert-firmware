# 离车泊车相关路径：原车请求与驾驶位模拟

[返回 Skill](../SKILL.md) · [协议总表](control-protocol.md#exit-parking) · [FSD 功能模块](features/04_fsd_activation.md#space_parking)

适用 P1.6.4 / V3.2 / `4d97f369`。依据原网页、反编译及 RISC-V 指令复核；本 Skill 不附原始镜像和完整反编译，以下地址是定位备注。未连接车辆或发送 CAN。

**已定位两条独立路径：退出 FSD 后请求原车开始泊车，以及跟随来源报文模拟主驾驶有人／已系安全带。** 所查路径中实际泊车运动交给原车系统；开门、离车后能否完成泊车尚未验证。

## 配置与时间线

| 网页配置 | 默认／范围 |
|---|---|
| `v13SpaceToSpaceEnabled` 自动激活泊车 | 关闭 |
| `v13ParkingDelayMs` | 2000 ms；0～10000 ms |
| `v13ParkingDurationMs` | 30000 ms；1000～60000 ms |
| `fsdDriverOccupiedSpoofEnabled` 驾驶位有人与安全带模拟 | 关闭、独立开关 |

CH `0x399` 的 `d0&0xF` 从3～6进入1/2触发，两次观察间隔≤1500ms。网页枚举为0 DISABLED、1 UNAVAILABLE、2 AVAILABLE、3 ACTIVE_NOMINAL、4 ACTIVE_RESTRICTED、5 ACTIVE_NAV、6 ACTIVE_FSD；边沿不含变为0。默认退出后2秒进入请求窗口，退出后32秒结束；移动暂停覆盖，窗口计时继续。

泊车构造与发送前均要求FSD总开关、泊车开关、通信和CH TX有效，最新399为1/2、年龄≤1500ms、armed有效且在窗口内。还要求CH257连续两帧零车速，相邻间隔≤100ms，最新速度年龄≤100ms。

参数名含v13，但所查触发、构造、发送前验证及UI显隐没有显式协议13限制；不能据此证明全部车型／协议兼容。

## 字段与构造

| 线路 / mask | ID / DLC / MUX | 字段、方向与时限 |
|---|---|---|
| CH / 1 | `0x399` / 正常8，无MUX筛选 | RX：d0低4bit，3～6→1/2触发；连续性和后续年龄≤1500ms |
| CH / 1 | `0x257` / 8，无MUX筛选 | RX：`raw=(d6<<5)\|(d5>>3)`，raw500为零；连续2帧、间隔／年龄≤100ms |
| CH / 1 | `0x293` / 8，无MUX筛选 | RX→TX：d3高4bit=C；d6高4bit计数+1；d7校验；来源+20000µs截止 |
| PARTY / 4 | `0x30A` / 8，无MUX筛选 | RX→TX：d0低3bit=1、bit3..4=1；d6高4bit计数+1；d7校验；来源+5000µs截止 |
| VEH / 2 | `0x3A1` / 8 / d6低4bit=2 | RX：占用d0bit7；带状态d3bit6=1且d4bit0=0；两帧满足、间隔／年龄≤300ms |

三路均500kbit/s。普通Frame的payload在对象+5..+12，DLC在+4，bus在+13；表中已经换算为payload字节号。

泊车构造器`0x480C76A2`复制CH293，来源d3高四位已为C则跳过：

```c
out = src;
out.d[3] = (src.d[3] & 0x0F) | 0xC0;
out.d[6] = (src.d[6] & 0x0F)
         | (((src.d[6] & 0xF0) + 0x10) & 0xF0);
out.d[7] = (0x95 + sum(out.d[0..6])) & 0xFF;
```

计数模16递增，其余位保留。来源时间缺失时取当前微秒时间。提交进入stream19；`0x480C6318`再次检查窗口、状态、零车速，通用层另查线路、传输许可与owner/generation。失去已确认静止时，`0x480DA2A8`调用`0x4805932A(...,19)`撤销请求。到期停止覆盖，未发现专用取消泊车payload；不能推导原车在此时必定停止泊车。

**来源有效性边界：** 399处理器计算seed9C校验，但错误校验及非8字节分支仍可到达局部泊车边沿更新，不能补写严格399校验／DLC门控。293构造器没有局部来源校验检查，输出会重算。所查接收回调`0x4810A7E4→0x48109D5A`未发现统一的399 payload校验拒绝；底层过滤的全部边界仍未恢复。

模拟构造器`0x480CB95C`要求PARTY30A DLC8、seed0D来源校验合格、模拟开关、通信、PARTY TX与传输许可。无局部FSD总开关、FSD运行、泊车窗口、零车速或关门限制。来源已有人且系带、计数重复或pending未结束时跳过；终态等待超过40ms会清理。

```c
out = src;
out.d[0] = (src.d[0] & 0xE0) | 0x09;
out.d[6] = (src.d[6] & 0x0F)
         | (((src.d[6] & 0xF0) + 0x10) & 0xF0);
out.d[7] = (0x0D + sum(out.d[0..6])) & 0xFF;
```

此路径stream8、提交owner11、token类别10。`0x480CCF42`只读VEH3A1，要求MUX2与seedC0校验合格，累积连续两次“有人且带状态满足”的采纳观察。内部TX标志由发送终态更新；公开`driverSeatSpoofActive/driverOccupiedSpoofActive`由`0x4805ABF4`组合判定：开关启用、内部TX成功、最近成功TX与最近3A1反馈均≤300ms且非零、反馈连续次数≥2。它不是泊车完成反馈，也不证明反馈由模拟造成。

另外缓存收到的30A带状态；`0x48105658`自动换挡读取构造前的输入缓存（有效、≤300ms、带值1、确认≥2）。本地输出修改不回写缓存；上游是否完全剔除自身发送回波尚未确认，不能保证所有缓存都只是真实传感器值。

## 定位与缺口

- 399边沿：`0x480D8F08`，关键指令`0x480D9390..93DA`、`0x480D98CA..98F0`。
- 293请求：`0x480C76A2`，d3写入`0x480C78B8`，计数`0x480C78BC`，校验`0x480C78EC`。
- 发送前复检：`0x480C6318`，关键分支`0x480C6698..676A`。
- 30A模拟：`0x480CB95C`，d0写入`0x480CBB8C`，计数`0x480CBB88`，校验`0x480CBBAE`。
- 反馈与真实带缓存：`0x480CCF42`；提交／终态`0x480DB9D4/0x480DF834`。

所查路径没有离座／开门触发和车门关闭模拟。门、锁、摄像头、钥匙等如何影响原车泊车，完整完成反馈及车型兼容仍需确认。增强AP/智能召唤兼容配置属于另一功能。


## 后续确认：门、完成计数、增强AP

门解析链为`0x480CCF42→0x48042BB2→0x480422D8/0x4804220C`，用于迎宾灯。要求VEH、DLC8、来源有效且≤500ms、generation非零及对象+1B/+1C元数据为0；本解析器没有独立payload求和校验。

| 输入 | 门字段 | 网页门名 |
|---|---|---|
| VEH102 | `((d1>>6)\|(d2<<2))&15` | 左前 |
| VEH103 | 同上 | 右前 |
| VEH102 | `(d2>>2)&15` | 左后 |
| VEH103 | 同上 | 右后 |

raw2累计关闭确认至2；raw1/5在先前两次关闭之后产生开门边沿；raw3/4保留状态并刷新时间；0或≥6清无效。间隔超过500ms清历史。VEH3C2 MUX0的`(d6>>2)&3`参与左前空座判定：1有效且空，2有效但非空，0/3无效；迎宾模式0要求对应空座条件，模式1放宽。**293泊车和30A模拟的已查门控没有读取这组迎宾门缓存，未找到这两条路径伪装关门。**

`fsdParkLaunchCompleteCount`属于P挡出发：`0x481062C4`在等待新399阶段要求DAS状态6（ACTIVE_FSD）、来源≤500ms、399观测代数变化后增加计数。不是到达车位／回P的泊车完成；网页launch状态6的“已完成”指进入FSD。它与293退出后请求是两个流程。

增强AP配置cfg+2B经`0x4809EC88`打包CH策略bit4／VEH策略bit2，再由`0x4FF230E8`解包，`0x4FF232BE`在对应线路3FD DLC8 MUX1清d2 bit3，V14另设d5 bit7；受线路运行许可限制。该链没有给出完整召唤会话、目标、路线或完成反馈。

公开Active字节映射已核对：device+9094（TX标志）、+9095/+9098（反馈次数／时间）、+90A4（成功TX时间）→组合判定+1D83→公开+1987。设备基址4FF60E20，快照4FF61A00=device+BE0，因此两接口均取快照偏移DA7。不要再将公开Active仅解释为TX终态。

仍需确认原车293接受／拒绝与任务阶段、开门离座后的继续条件、真正完成／取消反馈、30A与399的底层自回波处理，以及匹配车型版本。已找到的输入字段和固件请求操作不能替代这些原车执行证据。
