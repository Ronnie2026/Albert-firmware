# Albert-firmware

Albert 固件与技术参考资料整理。上游仓库：[204442021/Albert-firmware](https://github.com/204442021/Albert-firmware)。

## 先区分包内两部分

**ZIP 同时包含 S3 双 CAN 工程和 P4 三 CAN 逆向资料；逆向对象并非只有双 CAN。**

- `firmware/`：ZIP 外层的 ESP32-S3 双 CAN PlatformIO 工程，与正式 P4 工程的关系未确认。
- `技术参考/逆向分析资料/`：ZIP 内 `Albert/reverse/` 的 P4 三 CAN 逆向资料，包含 CH / VEH / PARTY 三通道信息、反编译和部分重建代码。
- 逆向记录针对 `4d97f369` 构建；当前上游 OTA 文件名标识为 `8915f5c7`。相同 P1.6.4 版本号不代表构建相同。

详见 [P4 三 CAN 与 S3 双 CAN 关系核对](技术参考/P4三CAN与S3双CAN关系核对.md)。

## 开发入口

工程使用 PlatformIO + Arduino，配置为 ESP32-S3、16MB Flash，双 CAN 为 MCP2515 + TWAI。构建时显式指定环境：

```sh
cd firmware
pio run -e main
```

导入时保持原源码功能不变，未执行编译、烧录或实车验证。原默认构建环境为报文回放 `can_b_replay`，`compile.sh` 默认则为 `can`；使用前请先阅读源码导入说明。

## 风险提示

**本仓库当前属于研究资料和未验证工程，不能作为可直接接入车辆的成品方案。**

1. **车辆控制风险**：CAN 注入、转发和录制报文回放可能改变车辆状态。涉及 NAG、方向盘提示、速度补偿、换挡、摄像头及辅助驾驶的功能可能影响驾驶员提示或车辆行为。请勿将未经验证的固件或回放数据用于道路驾驶，也不要以此替代驾驶员监控和接管职责。
2. **不同环境的发送行为不同**：`main` 的原说明采用默认关闭 TX 的策略，但不能推广到全部环境。`can_gateway` 使用 normal 模式并会 ACK，回放环境也会切换 normal 模式；网关的“隔离”指报文过滤，不代表电气隔离或完全被动监听。直接执行默认 `pio run` 会选择 `can_b_replay`，必须先检查目标入口、发送逻辑和配置。
3. **硬件适配风险**：ESP32-S3 与 ESP32-P4、双 CAN 与三 CAN，以及 P4 V1.3 / V3.2 的固件不可按名称相似而混刷。接线、收发器电平、供电、终端电阻和总线速率均需与实际硬件核对，优先在与车辆断开的测试台验证。
4. **升级与恢复风险**：FULL/bootstrap 与 OTA 镜像用途不同，选错镜像或分区配置、升级中断电可能导致设备无法启动或丢失配置。升级前准备匹配的有线恢复方式；作者要求 OTA 前通过车辆“安全”菜单关闭整车电源，并禁止行驶中 OTA。
5. **网络与数据风险**：原工程包含固定热点凭据和调试管理接口，不能默认视为安全的远程管理服务。请勿直接暴露到公网；抓包、日志、Wi-Fi 配置和云端上传内容在共享前应检查敏感信息，云端接入的数据范围需单独核实。
6. **构建与兼容风险**：原 README、脚本和 PlatformIO 的默认入口不一致，部分依赖未锁定版本。编译成功也不能证明报文语义、吞吐、故障恢复或车型兼容性正确；车辆软件更新后应重新验证。
7. **来源与授权风险**：公开下载不等于已获得修改、再分发或商业使用授权；逆向资料也不能自动视为原始源码。使用和分发前需核对原文件授权及相关权利，本仓库不额外授予第三方资料的使用权。
